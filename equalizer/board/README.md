# On-board run: CNN + DFE equalizer on the PYNQ-Z2

Runs the deployed design (8-bit CNN + 2 decision-feedback taps, 200 MHz, `checkpoints/hw_v2`) on the board and
checks it against the golden integer model on the whole fresh 4M-symbol test set.

## Files (copy all five to one folder on the board)

| File | What | Source |
|---|---|---|
| `cnn_eq.bit`, `cnn_eq.hwh` | overlay (same base name) | copied from `checkpoints/hw_v2/.../overlay/` |
| `board_vectors.npz` | 336 parameter words, 20 frames × 200,000 symbols of int8 input codes, golden int16 outputs, true bits | `scripts/make_board_vectors.py` |
| `cnn_eq_pynq.py` | driver + full test (pynq + numpy only) | this folder |
| `cnn_eq_pynq.ipynb` | step-by-step notebook (uses the driver) | this folder |

The `.bit`, `.hwh` and `.npz` are regenerated by `scripts/make_board_vectors.py` (run from `equalizer/` with
`PYTHONPATH` set to it) and are not kept in git.

## Steps

1. Boot the PYNQ-Z2 from its PYNQ SD card and connect it by Ethernet. Open Jupyter in a browser: `http://<board IP>:9090`
   (the factory default is `192.168.2.99` with a static laptop address in `192.168.2.x`, or `http://pynq:9090` on a
   router) and log in.
2. Create a folder, e.g. `cnn_eq`, and upload the five files with Jupyter's **Upload** button (or copy them over the
   board's `xilinx` network share).
3. Open `cnn_eq_pynq.ipynb` and run all cells. The full test takes well under a minute.
   Alternative without the notebook: a Jupyter terminal, `cd` into the folder, `sudo python3 cnn_eq_pynq.py`.
4. Send back `board_results.json` and `board_histogram.png` (written into the same folder), plus the PYNQ version
   the first cell prints.

## What a good run looks like

- core found: `ID 0x4E455131`, `SHAPE 0x04090304`, 336 parameters;
- pass 1: **0 output mismatches**, **2 bit errors in 3,997,440 bits** (the report's 5.0e-7);
- pass 2: counters exact (20 frames, 8,000,000 input beats, 4,000,000 output beats); core throughput close to
  97.5 MSym/s (0.975 samples per 200 MHz cycle). Wall-clock throughput is lower (Python and the 100 MHz DMA
  domain add per-frame overhead); both are recorded.
- final line `PASS`.

## If something goes wrong

- `wrong core: read ...`: the overlay is not the deployed one (check the `.bit`/`.hwh` pair) or the PL did not load.
- `AttributeError: ... eq` / `dma`: an old PYNQ image may not bind the IP names; the driver needs `ol.eq` (DefaultIP)
  and `ol.dma` (AXI DMA driver), both in `ol.ip_dict`.
- a DMA `wait()` that never returns: the stream stalled; note the counters (`eq.counters()`) and reload the overlay.
- mismatches with 0 bit errors added: still report them; the outputs must match exactly.

Offline, the driver and notebook are tested against a simulated PYNQ: `python -m pytest -q tests/test_board_driver.py`.
